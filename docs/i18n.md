# Internationalization (i18n)

French is the first non-English locale. UI chrome (nav, footer, language switcher) is translated; blog bodies stay English for now.

## Message resolution

| File | Role |
|------|------|
| `messages/en.json` | Source of truth |
| `messages/fr.generated.json` | Machine-translated fallback (committed; not rebuilt on every `next build`) |
| `messages/fr.manual.json` | Human overrides (win over generated) |

Merge order at runtime: **en → generated → manual**.

## URLs

- English (default): `/`, `/blog`, `/studio`, …
- French: `/fr`, `/fr/blog`, `/fr/studio`, …
- Admin stays English-only at `/admin` (outside locale routing)

## Refresh machine translations

```bash
GOOGLE_TRANSLATE_API_KEY=... npm run i18n:translate -- --to fr
```

Options:

- `--to fr,es` — target locales
- `--force` — retranslate keys missing from manual (does not overwrite `*.manual.json`)

Without an API key the script exits; shipping uses the committed `*.generated.json` files.

## Add a manual French fix

Edit `messages/fr.manual.json`:

```json
{
  "nav": {
    "openStudio": "Lancer le studio"
  }
}
```

## Add a new UI string

1. Add the English key to `messages/en.json`
2. Run `npm run i18n:translate -- --to fr` (or hand-edit `fr.generated.json` / `fr.manual.json`)
3. Use `useTranslations('…')` / `getTranslations('…')` in the component

## Blogs

Article bodies remain English. `/fr/blog/...` shows a short note that the article is in English. Full blog localization will use separate content files later (not `next-intl` JSON).
