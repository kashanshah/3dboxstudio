# Internationalization (i18n)

## Locales

| Locale | URL prefix | Indexed (initial rollout) |
|--------|------------|---------------------------|
| `en` (default) | none (`/`, `/blog/...`) | yes |
| `es` | `/es` | yes |
| `fr` | `/fr` | yes |
| `de` | `/de` | yes |
| `zh` | `/zh` | **noindex** until content review |

English URLs stay unprefixed (`localePrefix: "as-needed"`). There is no `/en/` migration.

`localeDetection` is **off** — Googlebot is never redirected by browser language.

## Message resolution

| File | Role |
|------|------|
| `messages/en.json` | Source of truth |
| `messages/{locale}.generated.json` | Machine / bulk translations |
| `messages/{locale}.manual.json` | Human overrides (win over generated) |

Merge order: **en → generated → manual**. Missing keys fall back to English; in development, missing keys are logged.

```bash
GOOGLE_TRANSLATE_API_KEY=... npm run i18n:translate -- --to fr,es,de,zh
```

## SEO

- Self-referencing canonicals per locale for fully translated pages (`/`, `/studio`, translated blogs)
- Reciprocal `hreflang` + `x-default` (English) via metadata and sitemap xhtml links
- Thin pages (FAQ, contact, privacy, terms, blog index) under non-English locales: **noindex**, canonical → English, omitted from sitemap
- Blog posts without a translation: **404** for that locale (no thin shells)
- Localized title/description for landing + studio (`src/seo/localePageMeta.ts`)

## Language switcher

Navigates to real locale URLs. If the target page is not translated (e.g. a blog slug missing in FR), falls back to the locale homepage.

## Blogs

| File | Role |
|------|------|
| `src/content/blogPosts.ts` | English source |
| `src/content/blogLocales/{locale}.ts` | Overlays (title, description, sections, FAQs) |

Currently translated:

- `how-to-create-3d-product-box-mockup-online` → French (`/fr/blog/...`)

Add more overlays in `src/content/blogLocales/` and register them in `index.ts`.
